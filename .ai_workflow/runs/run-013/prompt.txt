项目名称：inkos 小说生成项目

当前任务：任务五点八：Book-level Resource Schema 与章节阶段化 Resource Plan

当前子任务：5.8B-FIX：修复 run-012 抽象边界缺口，移除资源名特判并补齐 publish-ready chapter status 硬门禁

Design Anchor：
- `.ai_workflow/01_design.md` 的“章节生成层”：资源变化必须由 Resource Engine 或明确 closure 语义支撑，LLM 不得临时发明收益、消耗或余额。
- `.ai_workflow/01_design.md` 的“审稿增强层”：资源未闭合不得 ready-for-review；no-change 章节必须区分“无变化已闭合”和“检查缺失”。
- `.ai_workflow/01_design.md` 的“发布优化层”：发布前必须汇总资源闭合状态，不得用导出或润色掩盖系统性缺陷。
- `.ai_workflow/01_design.md` 的“Resource Engine 与故事性升级的关系”：Resource Engine 是系统流小说的确定性数值底座，防止数值污染、资源闭合失败、LLM 乱编收益/消耗。
- `.ai_workflow/01_design.md` 的“No-Change Resource Closure 的设计目标”：区分没有资源变化与资源检查缺失，对无资源变化章节输出明确 closure 结论。

当前任务对应 `02_todo.md`：
- `5.8B-FIX：修复 run-012 抽象边界缺口，移除资源名特判并补齐 publish-ready chapter status 硬门禁`

当前任务为什么没有脱离 `01_design.md`：
本轮不是新增功能，也不是修某本书输出，而是修复 run-012 未守住的抽象边界。它服务于章节生成层的 Resource Plan 约束、审稿增强层的资源闭合判断、发布优化层的资源硬门禁。

背景：
run-012 已实现 5.8B 的大部分改动，但 Codex review 判定 FAIL，阻断点有两个：
1. `packages/core/src/agents/resource-plan.ts` 新增 `system_bootstrap` 逻辑仍直接判断 `params.openingBalances["民望值"]` 和 `params.openingBalances["联邦币"]`，违反“不能写成资源名特例”的核心约束，也会让其他 book-level resource schema 的系统开篇不稳定。
2. `packages/cli/src/commands/review.ts` 的 publish-ready 资源硬门禁只读 resource consistency report，没有读取 chapter index 的 `state-degraded` / `blocked-resource-plan` 状态；如果 resource report 缺失或未标 blocking，仍可能放行已降级/阻断章节。

本轮核心目标：
1. 把 `system_bootstrap` 的 allowedEvents / balance_claim 生成改成 schema-driven：从 `resourceRules.resources` 与 `openingBalances` 推导，不允许判断具体资源名。
2. publish-ready 读取 chapter index，并对 `state-degraded` / `blocked-resource-plan` 返回 `BLOCKED_BY_RESOURCE`，即使 resource report 缺失或不 blocking。
3. 补齐测试，证明非 `民望值/联邦币` 资源 schema 也能进入正确 bootstrap 计划，publish-ready 能按 chapter index 状态阻断。
4. 不扩大战线，不新增任务六或 story-effectiveness 功能。
