Design Anchor：
- `.ai_workflow/01_design.md` 的“章节生成层”：资源变化必须由 Resource Engine 或明确 closure 语义支撑，LLM 不得临时发明收益、消耗或余额。
- `.ai_workflow/01_design.md` 的“审稿增强层”：资源未闭合不得 ready-for-review；no-change 章节必须区分“无变化已闭合”和“检查缺失”。
- `.ai_workflow/01_design.md` 的“发布优化层”：发布前不能携带数值污染，不能用导出或润色掩盖系统性缺陷。
- `.ai_workflow/01_design.md` 的“Resource Engine 与故事性升级的关系”：Resource Engine 是系统流小说的确定性数值底座，防止数值污染、资源闭合失败、LLM 乱编收益/消耗。
- `.ai_workflow/01_design.md` 的“No-Change Resource Closure 的设计目标”：区分没有资源变化与资源检查缺失，对无资源变化章节输出明确 closure 结论，不误触发 BLOCKED / WARN。

真实业务验证：
- 本轮必须实际运行程序产生 post-5.7B 新输出，不能只读取旧 report。
- Claude Code 必须先用 `--help` 确认本地 CLI 参数，再执行真实业务链路：
  - `node packages/cli/dist/index.js write next --help`
  - `node packages/cli/dist/index.js review publish-ready --help`
- 所有真实业务验证命令必须后台运行，不要直接在 console 前台运行。原因：console 运行超时时间通常只有 10 分钟，`write next` 等真实链路经常超过该时间。
- 后台运行必须记录 PID、日志和退出码。建议先创建 `.ai_workflow/runs/run-009/logs/`。
- 后台命令模板：
  - `nohup sh -c '<REAL_COMMAND>; echo $? > .ai_workflow/runs/run-009/logs/<name>.exit' > .ai_workflow/runs/run-009/logs/<name>.log 2>&1 & echo $! > .ai_workflow/runs/run-009/logs/<name>.pid`
- 轮询方式：
  - `cat .ai_workflow/runs/run-009/logs/<name>.pid`
  - `ps -p $(cat .ai_workflow/runs/run-009/logs/<name>.pid)`
  - `tail -n 120 .ai_workflow/runs/run-009/logs/<name>.log`
  - 命令结束后读取 `.ai_workflow/runs/run-009/logs/<name>.exit`

  - `node packages/cli/dist/index.js write next 我使用系统当上美国总统3 --count 1 --words 1200 --context "任务五资源闭合验证：本章聚焦对话、压力升级、计划推进或局势判断；不要新增收益、消耗、兑换、技能变化或余额声明；不要为了资源闭合补写任何资源事件。" --json`

  - `nohup sh -c 'node packages/cli/dist/index.js write next 我使用系统当上美国总统3 --count 1 --words 1200 --context "任务五资源闭合验证：本章聚焦对话、压力升级、计划推进或局势判断；不要新增收益、消耗、兑换、技能变化或余额声明；不要为了资源闭合补写任何资源事件。" --json; echo $? > .ai_workflow/runs/run-009/logs/write-next.exit' > .ai_workflow/runs/run-009/logs/write-next.log 2>&1 & echo $! > .ai_workflow/runs/run-009/logs/write-next.pid`

- 验证目标：
  - resource consistency 新 report 中存在 `closureStatus: "no_change_closed"`。
