================================================================================
BIZ REPORT — 5.7B-2 No-Change Resource Closure 判定语义实现
================================================================================

## 实现内容

定义了 4 种 closure 状态并在 Resource Consistency 报告中输出：

| closureStatus | 含义 | 触发条件 |
|---------------|------|---------|
| no_change_closed | 已检查，确认无资源变化 | 无资源事件、无 issue、无 plan violation、非 blocking |
| normal_closed | 有资源事件，计算闭合 | 有资源事件、无 issue、无 violation、非 blocking |
| not_checked | 缺少检查或 Resource Plan | 无 plan 且无事件（无法确认检查是否执行） |
| resource_failed | 资源异常或阻断 | blocking=true、FAILED、WARN 或有 plan violation |

## 关键行为保证

1. no-change 章节不会触发错误 BLOCKED/WARN — 确认通过 5.7B-1 盘点
2. 真实资源异常仍保持 FAILED/WARN/blocking — closureStatus 判定中 resource_failed 优先级最高
3. not_checked 与 no_change_closed 严格区分 — 无 plan 不能伪装成已闭合
4. 不允许 LLM 临时补写收益/消耗/余额 — 未修改 writer/planner 逻辑

## 边界情况处理

- no_resource_change plan 下有资源事件：closureStatus 根据实际 issue 情况判定
  （无 issue → normal_closed；有 issue → resource_failed），事件记录在 balanceMutationEvents
- WARN 状态：归入 resource_failed（非阻塞但有异常）
- FIXED 状态（自动修复）：归入 normal_closed（已修复，可视为闭合）

## 下游消费路径

- Resource consistency report JSON: `{ ..., "closureStatus": "no_change_closed" }`
- Resource consistency report MD: `- Closure Status：no_change_closed`
- 程序账本 JSON（MD 内嵌）: `"closureStatus": "no_change_closed"`
- 类型导出：`import { classifyClosureStatus, type ClosureStatus } from "@actalk/inkos-core"`
