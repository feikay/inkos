# 按卷调整(宏观)

📂 `story/volume_outline.md`（本卷的宏观大纲剧情）

每次系统在为新章节自动生成 `chapter-intents` 细纲时，都会读取这个文件作为剧情依据。修改它们会自然引导后续所有章节意图的规划。

# 10章以前

📂 `story/first_10_chapter_plan.md`（前10章的粗略分章规划）

### 1. 为什么这个文件只有第一章的描述？
* **初始模板遗留**：`first_10_chapter_plan.md` 是你在创建这本书（初始化）时，系统自动生成的一个**初始规划骨架**。
* **增量规划**：系统在初始化时通常只生成第一章的精细描述（用来冷启动第一章的写作）。对于后续章节（第 2 章及以后），系统不会在最开始就写死详细规划，而是采用“增量生成”的机制——通过读取 `volume_outline.md`（分卷宏观规划）来动态规划后续章节。

### 2. 为什么内容与原文有差异了？
* **写作过程中的“剧情漂移（Refinement）”**：大纲是地图，不是囚牢。在实际撰写和 Polishing 过程中，AI（或你做出的微调）对剧情进行了优化以增强可读性：
  * **黑板字样**：从“香港回归倒计时7天”改成了更具学业压迫感的“距高考还有十四天”。
  * **第一章结尾钩子**：从原本干瘪的“摸着三毛钱看窗外”，改写成了高张力的“手揣钢镚，在全班惊叫中直接推门迎向拿钢管的黄毛”。
* **状态同步**：系统每次写新一章（`write next`）时，都是基于你**实际写完并 Approve 的正文**（即 `chapters-reviewed/` 下的最终文件）和 `current_state.md` 来生成下一章细纲的，而不会去死板地套用这个过时的初始规划。所以，原文一旦发生改变，后续的规划会自动适配新剧情，而初始大纲文件不会被系统自动往回修改。

### 3. 如果想调整后续章节（如第 2-10 章）该怎么做？

由于 `first_10_chapter_plan.md` 目前是空的，这反而给了你极大的自由度：

1. **宏观控制（推荐）**：
   你可以直接在 `first_10_chapter_plan.md`中，手动添加你想要的第 2-10章的粗略大纲。例如：
   
   ```markdown
   ### 第4章
   - 主角随桑塔纳来到望江茶楼，与龙爷面对面博弈。
   - 主角利用前世记忆点破龙爷在省城的竞争对手以及马国良私吞的走私烟。
   - 达成协议：主角帮龙爷洗白这批货，龙爷给主角三天时间，并提供农贸市场摊位的庇护。
   ```
   *AI 在跑 `plan chapter` 生成下一章细纲时，会读取这个文件，并自动把你的这些想法融进 `chapter-intents` 细纲里。*
   
2. **微观控制（更精准）**：
   不需要动全局大纲，直接在写每一章前跑 `plan chapter`，然后去 `story/runtime/chapter-[章节号].intent.md` 里面直接改那一章的 `.md` 细纲文件。

# 10章以后

10 章以后，系统设计了两个更符合中后期创作习惯的替代文件和工具：

## 方法 A：利用 `current_focus.md`（当前聚焦）—— 强烈推荐

- 📂 **位置**：`story/current_focus.md`

- 如何改：在这个文件顶部的`## 当前重点`中，可以直接写下针对即将到来章节的具体指向性要求。例如：

  ```
  ## 当前重点
  
  - 第11章必须完成：主角通过干货生意赚到第一笔五千元，并在饭店里再次偶遇张少华，发生第一次轻微口角冲突。
  ```

- **原理**：`current_focus.md` 是**全局常驻上下文**。无论是第 11 章还是第 100 章，系统生成细纲时都会优先读取“当前重点”里的描述。这非常适合用来做“滚雪球式”的即时目标控制。

## 方法 B：使用 `plan chapter` ➔ 手动修改意图卡

- 如何改：到了第 11 章时：
  1. 运行 `plan chapter` 生成 `story/runtime/chapter-[章节号].intent.md`。
  2. 打开 `chapter-[章节号].intent.md`，找到 **`## Goal`** 或 **`## Outline Node`**，修改里面的剧情大纲。。
  3. 保存后运行 `write next` 撰写。
- **原理**：这是最强力、最精细的控制方式，不受任何章节限制，是中后期精修大纲的主力手段。

## 方法 C：保持 `volume_outline.md`（分卷规划）的更新

- 📂 **位置**：`story/volume_outline.md`
- **如何改**：这里面写着卷一（1-30章）、卷二（31-80章）的宏观走向。如果你对后续卷的走向有了新想法，随时在这里更新分卷的关键转折和核心冲突即可。

# 手动修改单章意图卡

在 `inkos` 的系统设计中，每一章的“细纲”被称为 **Chapter Intent（章节意图卡）**。

如果你想精准控制并调整下一章的走向，系统为你提供了一条非常科学的“两步走”工作流（**先规划，修改细纲，再撰写**）：

---

## 1. 应该改哪里？

系统的章节细纲文件存放在：
📂 `my-novel/books/重生1997/story/runtime/chapter-[章节号].intent.md` （比如第 4 章就是 `chapter-0004.intent.md`）

**具体的修改机制：**

1. **如果你直接运行 `write next`**，系统内部的流水线会强制重新执行： `读取 chapter-[章节号].intent.md` ➔ `LLM 重新编译生成 chapter-intents/[章节号].md` ➔ `交给 Writer 写正文`。
2. **正确的自定义工作流**：
   
   * **第一步：只生成细纲（Plan）**。在撰写前，运行命令：
     
     ```bash
     node packages/cli/dist/index.js plan chapter 重生1997
     ```
     *这个命令只会生成下一章的细纲文件 `story/runtime/chapter-[章节号].intent.md`，而不会开始写正文。*
   * **第二步：修改细纲**。打开生成的 `chapter-[章节号].intent.md` 文件，你可以直接修改 **`## Goal`** 或 **`## Outline Node`** 中的文字，写下你对这一章剧情的期望。
   * **第三步：正式撰写（Write）**。修改好并保存 `chapter-[章节号].intent.md` 后，运行正常的撰写命令：
     
     ```bash
     node packages/cli/dist/index.js write next 重生1997
     ```
     *此时，*系统在检测到没有外部 context 输入时，会通过 `loadPersistedPlan` **直接读取并复用** 你刚刚修改过的 `chapter-[章节号].intent.md` 作为输入，然后调用 LLM 编译出正确的 `chapter-intents/[章节号].md` 并写出正文。你的意志就会完美融入正文中！。

---

## 2. 在什么时候改？

* **针对下一章（即时控制）**：
  * **时间点**：在写完当前章（比如第3章 approve/export 完成）之后，**生成下一章（第4章）的正文之前**。
  * **步骤**：跑 `plan chapter` ➔ 手工修改并保存 `story/runtime/chapter-[章节号].intent.md` ➔ 跑 `write next`。
