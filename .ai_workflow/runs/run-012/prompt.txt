当前子任务：5.8B：实现 Book-level Resource Schema、章节阶段化 Resource Plan、fallback gate 与 publish-ready 资源门禁的最小抽象修复

Design Anchor：
- `.ai_workflow/01_design.md` 的“章节生成层”：资源变化必须由 Resource Engine 或明确 closure 语义支撑，LLM 不得临时发明收益、消耗或余额。
- `.ai_workflow/01_design.md` 的“审稿增强层”：资源未闭合不得 ready-for-review；no-change 章节必须区分“无变化已闭合”和“检查缺失”。
- `.ai_workflow/01_design.md` 的“发布优化层”：发布前必须汇总资源闭合状态，不得用导出或润色掩盖系统性缺陷。
- `.ai_workflow/01_design.md` 的“Resource Engine 与故事性升级的关系”：Resource Engine 是系统流小说的确定性数值底座，防止数值污染、资源闭合失败、LLM 乱编收益/消耗。
- `.ai_workflow/01_design.md` 的“No-Change Resource Closure 的设计目标”：区分没有资源变化与资源检查缺失，对无资源变化章节输出明确 closure 结论。

当前任务对应 `02_todo.md`：
- `5.8B：实现 Book-level Resource Schema、章节阶段化 Resource Plan、fallback gate 与 publish-ready 资源门禁的最小抽象修复`

当前任务为什么没有脱离 `01_design.md`：
本轮不是修某本书、某个章节或某个资源名，而是把 5.8A 盘点出的缺口实现为 Resource Engine 的通用规则：book-level resource schema、章节阶段化 Resource Plan、schema/mode gated fallback、publish-ready / export 资源硬门禁。它仍属于章节生成层、审稿增强层和发布优化层的资源一致性底座。

背景：
run-011 已完成 5.8A 只读盘点，确认五个抽象缺口：全局默认资源污染、叙事金融数字误入强账本、缺少 `system_bootstrap` / `resource_rule_reveal` mode、fallback recovery 未按 schema/mode 分派、publish-ready/export 缺少资源硬门禁。本轮进入最小抽象实现。

重要原则：
- 不允许把修复写成某本书、某个资源名、某个章节的特例。
- 真实样本只是 evidence，修复必须抽象为程序规则、数据结构、prompt 约束或流程门禁。
- 不能直接编辑业务验证输出让结果通过。
- 常规研发循环不得修改 `.ai_workflow/01_design.md`。

本轮核心目标：
1. 实现 book-level resource schema gate：优先只让 `book_rules.md` 显式声明的资源类型进入强账本；没有声明时保留兼容回退。
2. 实现叙事金融数字过滤：普通价格、订单金额、打车费、外卖费、转账、工资等不应被自动纳入资源账本；系统面板、资源余额、兑换等上下文仍可进入 Resource Engine。
3. 新增通用 Resource Plan mode：`system_bootstrap` 和 `resource_rule_reveal`，用于系统/能力首次激活、规则揭示、初始任务发布等章节阶段。
4. 实现 fallback recovery 的 schema/mode gate：只有 schema 支持兑换且当前 plan mode 允许兑换时，才可选择 `defer_exchange`；否则走不发明收益/兑换的安全策略。
5. 实现 publish-ready / export 资源硬门禁：`blocking=true`、`closureStatus=resource_failed`、`state-degraded`、`blocked-resource-plan` 不得被发布或导出流程放行。
6. 补充测试与最小真实业务验证报告。
