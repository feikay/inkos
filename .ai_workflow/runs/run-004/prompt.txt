为什么没有脱离 01_design.md：
5.7B-3 延续 5.7B-2 已实现的 `closureStatus` 语义，目标是确保 resource consistency report 的 JSON/MD 输出能稳定表达 no-change closure，并为后续 publish-ready、continuity、review、export 消费提供明确字段。它服务于审稿增强层和发布优化层，不修改总体设计，不直接修复业务输出。

背景：
5.7B-2 已实现：
- `ClosureStatus` 类型；
- `classifyClosureStatus()`；
- `ResourceConsistencyPipelineResult.closureStatus`；
- runner 中 closureStatus 计算；
- resource consistency report JSON/MD 中初步输出 closureStatus；
- 相关单元测试通过。

5.7B-3 需要复核并补齐 report 输出语义，确保 no-change 章节能输出明确 closure 结论，而不是只依赖旧的 `noChangeInferred` / `closureSource` 组合。

本轮核心目标：
补齐 no-change closure report 输出，使报告消费者可以稳定区分：
- `no_change_closed`：已检查，确认无资源变化；
- `normal_closed`：有资源事件且资源计算闭合；
- `not_checked`：缺少必要检查，不能当作 no-change closure；
- `resource_failed`：资源异常、阻断或真实失败。
