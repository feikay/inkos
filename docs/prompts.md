# 重新章节结构提示词
```
修复第26章《暗河尽头前的死局：山门外的活路》的番茄发布版结构问题。

当前 report：
- 字数：2960，偏长
- 6段检查：3/6
- 缺失：Hook / Pressure / Payoff 
- 已具备：Attempt / Twist / Pull

只修改：
my-novel/books/葬渊魔经/chapters/0026_暗河尽头前的死局：山门外的活路.md

目标：
把本章修到至少 5/6，并控制在 1500-2500 字。

要求：

1. Hook：
- 重写开头前3-5行
- 必须直接出现异常 / 危机 / 人物冲突
- 禁止环境描写开头
- 开头要让读者立刻知道“云岚不简单”或“楚夜遇到危险”

2. Payoff：
- 保留原剧情主线
- 在中后段补一个明确爆点
- 必须有单句 moment
- 可选类型：
  - 认知爆点：那一刻，他看懂了云岚身上的问题。
  - 状态爆点：云岚体内的灵气，骤然失控。
  - 事件爆点：她掌心的符纹，裂开了。

3. Pull：
- 重写结尾最后3-5段
- 必须留下下一章钩子
- 结尾要出现新的问题 / 更大危机 / 未解身份
- 禁止平淡收尾

4. 字数处理：
- 当前4002字太长，压缩到1500-2500字
- 删除重复说明、冗长环境描写、重复心理活动
- 不删除关键剧情节点

5. 禁止：
- 不新增大设定
- 不改变后续状态
- 不改变主角和云岚的核心关系方向
- 不整章完全换剧情
- 不输出解释，只输出修复后的完整章节正文

结构必须满足：
Hook → Pressure → Attempt → Twist → Payoff → Pull
```

# 修复开篇重复问题
```
项目：inkos 小说生成
目标：扫描并修复《葬渊魔经》已输出章节的“开头首句相似 / 模板化开篇”问题。
阶段：番茄发布前正文质量修复。

你要做的事：

1. 扫描目录：
   my-novel/books/葬渊魔经/chapters/

2. 重点检查每章正文开头的前 1～3 句，识别以下问题：
   - 连续章节首句结构高度相似
   - 多章重复使用类似句式，例如：
     “楚夜和云岚在暗河尽头的探索并未因之前的胜利而停下脚步”
     “随着深入，四周环境愈发……”
     “他们知道，这片……隐藏着更多秘密……”
   - 开头过于概括、像 AI 过渡句
   - 缺少网文开篇的钩子、危机、动作、感官冲击

3. 输出一份报告：
   reports/fanqie-opening-dup-report.md

报告内容包括：
   - 章节号
   - 原始首句
   - 与哪些章节相似
   - 相似原因
   - 是否需要修复
   - 建议修复方向

4. 自动修复需要修复的章节，但必须遵守：
   - 不改剧情主线
   - 不改人物设定
   - 不新增会影响后续剧情的大事件
   - 不删除已有关键道具、敌人、线索、战斗结果
   - 只重写每章开头 1～3 段，必要时轻微衔接后文
   - 保留章节原有核心信息
   - 保持玄幻网文风格
   - 开头要更有吸引力，优先使用：
     动作开场 / 危机开场 / 异象开场 / 悬念开场 / 感官压迫开场

5. 修复风格要求：
   - 避免“继续探索”“并未停下脚步”“真正的危险才刚刚开始”等模板句
   - 避免连续章节都用“楚夜和云岚……”作为首句
   - 每章开头要有不同切入点：
     例如：
       第14章可以从“暗河水面突然倒流 / 怨念抬头”切入
       第15章可以从“妖兽尸体护着玉牌 / 资源异常”切入
       第16章可以从“玉牌发烫 / 黑袍人现身”切入
   - 首句尽量短、有画面、有冲击力
   - 每章开头要直接进入场景，不要先总结上一章

6. 修复后再次扫描：
   - 确认没有连续 3 章以上使用相似开篇结构
   - 确认每章首句差异明显
   - 确认正文没有被误删
   - 确认章节标题、正文格式不被破坏

7. 最后输出：
   - 修改了哪些章节
   - 每章原首句
   - 每章新首句
   - 是否改动超过开头 3 段
   - 是否存在需要人工确认的章节

执行方式：
   - 先生成报告
   - 再修复明显重复的章节
   - 修复后再生成复查报告
   - 不要改 scripts / cli / pipeline 逻辑，除非发现现有导出或生成流程中存在导致重复开篇的明确原因
```

# 精修表达重复问题
```
项目：inkos 小说生成
目标：对《葬渊魔经》进行“开头去模板化 + 中段去复读表达”质量提升
阶段：番茄发布前二轮精修

背景：
已完成第一轮修复（首句重复问题已解决），但仍存在：
- 正文中段出现模板句反复使用
- 多章使用相同表达推进剧情（如“继续深入”“真正的危险才刚刚开始”）
- 战斗、探索、发现资源流程高度同质化

本轮目标：
在不改变剧情主线的前提下，提升“表达多样性 + 节奏差异”

---

你要做的：

## 1. 扫描范围
my-novel/books/葬渊魔经/chapters/

---

## 2. 检测问题（新增维度）

除了开头外，重点检测：

### A. 模板句复用
例如：
- “真正的危险才刚刚开始”
- “他们继续深入……”
- “隐藏着更多秘密”
- “这一切只是冰山一角”

### B. 段落结构重复
例如：
- 战斗 → 击杀 → 掉落 → 玉牌
- 探索 → 感知 → 遇敌 → 战斗

### C. 情绪词泛化
例如：
- 紧张 / 压抑 / 危险 / 神秘（重复密集）

---

## 3. 修复策略（重点）

### 只允许：
- 替换表达（同义改写）
- 调整句式
- 插入更具体的细节（感官 / 动作 / 物理反馈）

### 严禁：
- 改剧情走向
- 改事件顺序
- 改战斗结果
- 新增关键设定

---

## 4. 表达优化规则（核心）

### ❌ 删除模板句：
- 不允许再出现：
  “真正的危险才刚刚开始”
  “他们继续深入”
  “隐藏着更多秘密”

### ✅ 替换为具体表达：

示例：

原句：
> 真正的危险才刚刚开始

改为：
> 石壁上的符文忽然齐齐亮起。

---

原句：
> 他们继续深入暗河尽头

改为：
> 楚夜踩过那片碎骨，脚下忽然一沉。

---

原句：
> 这里隐藏着更多秘密

改为：
> 那块石碑背面，还有未干的血迹。

---

## 5. 节奏打散（重要）

要求：

- 连续章节不能都走：
  战斗 → 掉落 → 玉牌

必须插入变化：
- 有的章先异象
- 有的章先资源
- 有的章先陷阱
- 有的章先人

---

## 6. 输出

生成报告：
reports/fanqie-style-variation-report.md

包含：

- 修改章节
- 删除的模板句
- 替换后的句子
- 是否影响节奏
- 是否建议回改 writer 模板

---

## 7. 额外任务（关键）

如果发现模板句来自同一生成模式：

输出：

reports/writer-template-issue.md

内容包括：
- 哪些句式来自 writer
- 出现频率
- 建议如何修改 writer prompt（从源头解决）

---

执行顺序：

1. 扫描
2. 输出问题报告
3. 批量修复
4. 再扫描验证
5. 输出最终报告
```
