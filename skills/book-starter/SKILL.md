# Book Starter - 新书创建向导技能

## Overview

本技能用于简化新书创建流程，通过交互式向导帮助用户快速创建新书籍。

**核心流程**：生成候选书名和主题 → 用户选择 → 创建书籍 → 匹配度分析 → 确认/重新生成

---

## When to Use

用户询问以下类型问题时触发：

- "新开一本玄幻书"
- "创建一本都市小说"
- "新建书籍，都市题材"
- "帮我开个新书，要系统流的"
- "我想写一本新书"
- "新开XX类型的书"（XX为任何题材类型）

---

## Workflow

### Step 0: 加载系统支持的中文题材列表

**重要**：在解析用户需求前，必须先动态读取系统支持的中文题材列表。

#### Step 0.1: 扫描 genres 目录

```bash
# 读取所有 genre 文件
ls packages/core/genres/*.md
```

#### Step 0.2: 判断是否为中文题材

**判断标准**：读取每个文件的 frontmatter 中的 `name` 字段：
- 如果 `name` 包含中文字符 → 中文题材 ✅
- 如果 `name` 全是英文 → 英文题材 ❌ 忽略

```bash
# 伪代码
for file in packages/core/genres/*.md:
    read frontmatter:
        id          → 文件名（去掉 .md 后缀）
        name        → 题材名称（判断依据）
        description → 题材描述
    
    # 判断 name 是否包含中文
    if containsChinese(name):
        add to chineseGenres[]
```

**示例判断结果**：

| 文件名 | name 字段 | 是否中文 | 处理 |
|-------|----------|---------|------|
| `xuanhuan.md` | "玄幻" | ✅ 中文 | 加入列表 |
| `system.md` | "系统流" | ✅ 中文 | 加入列表 |
| `rebirth.md` | "重生流" | ✅ 中文 | 加入列表 |
| `urban.md` | "都市" | ✅ 中文 | 加入列表 |
| `xianxia.md` | "仙侠" | ✅ 中文 | 加入列表 |
| `isekai-zh.md` | "穿越/穿书" | ✅ 中文 | 加入列表 |
| `romance-zh.md` | "言情" | ✅ 中文 | 加入列表 |
| `cultivation.md` | "Cultivation" | ❌ 英文 | 忽略 |
| `litrpg.md` | "LitRPG" | ❌ 英文 | 忽略 |
| `horror.md` | "Horror" | ❌ 英文 | 忽略 |

#### Step 0.3: 生成中文题材映射表

将 `chineseGenres` 转换为映射表，用于匹配用户的口语化描述：

```json
[
  {
    "id": "xuanhuan",
    "name": "玄幻",
    "aliases": ["玄幻", "修真", "修仙玄幻"]
  },
  {
    "id": "system",
    "name": "系统流",
    "aliases": ["系统", "系统流", "系统文"]
  },
  {
    "id": "rebirth",
    "name": "重生流",
    "aliases": ["重生", "重生流", "重生复仇"]
  },
  {
    "id": "urban",
    "name": "都市",
    "aliases": ["都市", "都市生活", "城市"]
  },
  {
    "id": "xianxia",
    "name": "仙侠",
    "aliases": ["仙侠", "修仙", "修真"]
  },
  {
    "id": "isekai-zh",
    "name": "穿越/穿书",
    "aliases": ["穿越", "穿书", "穿越重生"]
  }
  // ... 其他中文题材
]
```

**注意**：如果用户输入的题材类型不在中文题材列表中，应该：
1. 提示用户当前系统支持的中文题材有哪些
2. 询问用户是否要使用 `other` 题材（通用题材）
3. 或者建议用户先查看 `inkos genre list` 命令查看所有支持的题材

---

### Step 1: 解析用户需求

从用户输入中提取：
- **题材类型**（genre）：如玄幻、都市、系统流、重生等
- **平台偏好**（可选）：如番茄、起点等
- **其他要求**（可选）：如章节字数、目标章数等

**题材匹配规则**：

1. 使用 Step 0 生成的中文题材映射表
2. 将用户输入的题材描述与 `name` 和 `aliases` 进行匹配
3. 匹配成功 → 使用对应的题材ID
4. 匹配失败 → 提示用户可选的中文题材列表

---

### Step 2: 生成3个候选书名和主题方向

基于用户选择的题材类型，生成3个不同的书名和主题方向。

**生成要求**：
1. **书名**：吸引人、符合题材特点、有网文感
2. **主题方向**：简要描述故事的核心设定、主线剧情、特色亮点
3. **差异化**：3个选项要有明显区别（不同主角设定/不同剧情走向/不同卖点）

**输出格式**：

```markdown
## 📚 为您生成了3个{题材}题材的书名方案

### 方案1：《{书名}》
**主题方向**：
- **核心设定**：[世界观/金手指/特殊设定]
- **主角设定**：[身份/性格/目标]
- **主线剧情**：[主要故事线]
- **特色亮点**：[独特卖点]

---

### 方案2：《{书名}》
**主题方向**：
- **核心设定**：[世界观/金手指/特殊设定]
- **主角设定**：[身份/性格/目标]
- **主线剧情**：[主要故事线]
- **特色亮点**：[独特卖点]

---

### 方案3：《{书名}》
**主题方向**：
- **核心设定**：[世界观/金手指/特殊设定]
- **主角设定**：[身份/性格/目标]
- **主线剧情**：[主要故事线]
- **特色亮点**：[独特卖点]

---

请选择您感兴趣的方案（1/2/3），或者说出您的修改意见。
```

**重要**：生成后，将3个方案的主题方向保存到内存中，供后续匹配度分析使用。

---

### Step 3: 用户选择后，创建书籍

用户选择方案后（如"我选方案1"或"就第一个"），执行以下操作：

#### Step 3.1: 确定书籍参数

- **书名**：用户选择的方案的书名
- **genre**：从 Step 1 解析的题材ID
- **platform**：默认 "tomato"（番茄），如果用户指定则使用用户指定
- **target-chapters**：默认 200，如果用户指定则使用用户指定
- **chapter-words**：默认 3000，如果用户指定则使用用户指定
- **lang**：根据 genre 自动判断（中文题材用 "zh"，英文题材用 "en"）

#### Step 3.2: 生成创意简报（Creative Brief）

**重要**：为了让 AI 生成的概要严格遵循用户选择的方案主题方向，需要先将方案的**主题方向**整理成结构化的创意简报。

**简报格式**（保存到临时文件，如 `/tmp/book-brief-{timestamp}.md`）：

```markdown
# 创意简报：《{书名}》

## 题材
{genre 中文名}

## 核心设定
{方案的 core-setting}

## 主角设定
{方案的 protagonist-setting}

## 主线剧情
{方案的 main-plot}

## 特色亮点
{方案的 highlights}

## 写作要求
- 严格遵循以上设定，不要偏离
- 世界观设定要具体，有辨识度
- 主角性格要鲜明，行为逻辑一致
- 剧情要有明确的爽点和节奏
```

**保存路径**：建议使用 `/tmp/book-brief-{timestamp}.md`，避免权限问题。

#### Step 3.3: 执行 book create 命令（使用 --brief 参数）

```bash
inkos book create \
  --title "{书名}" \
  --genre {genre} \
  --platform {platform} \
  --target-chapters {target-chapters} \
  --chapter-words {chapter-words} \
  --lang {lang} \
  --brief /tmp/book-brief-{timestamp}.md
```

**注意**：
- `--brief` 参数会让 AI **基于简报生成设定**，而不是完全自由发挥
- 这样生成的概要会**严格遵循用户选择的方案主题方向**
- 如果命令执行失败（如书名已存在），提示用户并询问是否更换书名
- 成功后，记录生成的 `book-id`（从命令输出中解析）

#### Step 3.3: 读取生成的概要信息

`inkos book create` 会生成书籍的基础结构和概要信息。需要读取以下文件获取概要：

1. **book.json** - 书籍基础信息
2. **story/story_bible.md** - 世界观设定（如果存在）
3. **story/author_intent.md** - 作者意图（如果存在）

将这些信息整理成概要输出。

---

### Step 4: 输出概要并分析匹配度

#### Step 4.1: 输出新书概要

```markdown
## 📖 新书创建成功！

**书籍信息**：
- 书名：《{书名}》
- 书籍ID：{book-id}
- 题材：{genre}
- 平台：{platform}

**AI 生成的概要信息**：

{此处输出从生成的文件中读取的概要信息，包括：}
- 世界观设定
- 主角设定
- 剧情大纲
- 其他重要设定
```

#### Step 4.2: 匹配度分析

将 AI 生成的概要信息与 Step 2 中保存的用户选择的方案的主题方向进行比对分析：

```markdown
## 🔍 主题匹配度分析

**原始方案主题方向**：
- 核心设定：{原始核心设定}
- 主角设定：{原始主角设定}
- 主线剧情：{原始主线剧情}
- 特色亮点：{原始特色亮点}

**AI 生成的实际概要**：
- 核心设定：{实际核心设定}
- 主角设定：{实际主角设定}
- 主线剧情：{实际主线剧情}
- 特色亮点：{实际特色亮点}

**匹配度评估**：
- ✅ 核心设定：{匹配/部分匹配/不匹配} - [具体说明]
- ✅ 主角设定：{匹配/部分匹配/不匹配} - [具体说明]
- ✅ 主线剧情：{匹配/部分匹配/不匹配} - [具体说明]
- ✅ 特色亮点：{匹配/部分匹配/不匹配} - [具体说明]

**综合匹配度**：{高/中/低} ({百分比}%)

{如果匹配度低，给出具体建议}
```

---

### Step 5: 用户确认

```markdown
---

是否确认使用此书作为最终版本？

- **确认**：输入 "确认" 或 "通过" 或 "OK"
- **重新生成**：输入 "重新生成" 或 "不匹配" 或 "回退"
- **修改设定**：直接说出您想要修改的内容
```

#### Step 5.1: 用户确认通过

如果用户确认通过：
```markdown
✅ 书籍创建完成！

**下一步操作建议**：
1. 开始写第一章：`inkos write next {book-id} --count 1`
2. 查看书籍信息：`inkos book list`
3. 修改书籍设定：`inkos book update {book-id} --xxx`
```

结束流程。

#### Step 5.2: 用户要求重新生成

如果用户不满意，执行回退操作：

1. **删除已创建的书籍**：
   ```bash
   inkos book delete {book-id} --force
   ```

2. **清除之前的候选方案**（可选，如果用户要求完全重新生成）

3. **返回 Step 2**，重新生成3个候选方案（可以有不同的侧重点）

4. 循环 Step 2 → Step 3 → Step 4 → Step 5，直到用户确认

#### Step 5.3: 用户要求修改设定

如果用户提出具体修改意见：
1. 根据用户的修改意见，调整参数
2. 可以选择：
   - 重新生成候选方案（返回 Step 2）
   - 直接修改当前书籍设定（使用 `inkos book update` 命令）

## 错误处理

### 书名已存在

如果 `inkos book create` 报错 "already exists"：
```markdown
⚠️ 书名《{书名}》已存在，请选择：

1. 更换书名，重新生成候选方案
2. 删除现有书籍，使用相同书名重建
3. 使用不同的书名创建
```

### book create 执行失败

如果命令执行失败：
```markdown
⚠️ 书籍创建失败，错误信息：{错误信息}

可能的原因：
1. 项目目录不正确
2. LLM 配置有问题
3. 其他错误

请检查后重试，或手动执行：
`inkos book create --title "..." --genre ...`
```

### 概要信息读取失败

如果无法读取生成的概要信息：
```markdown
⚠️ 无法读取完整的概要信息，但书籍已成功创建。

书籍ID：{book-id}
您可以直接查看生成的文件：
- book.json
- story/story_bible.md
- story/author_intent.md
```

## 高级功能

### 使用创意简报（Creative Brief）

如果用户在初始请求中提供了详细的创意想法，可以将这些想法保存到临时文件，然后使用 `--brief` 参数：

```bash
inkos book create --title "{书名}" --genre {genre} --brief {temp-brief-file}
```

### 使用网文模板

对于特定题材，可以使用模板参数：

```bash
# 目前仅支持 xuanhuan 模板
inkos book create --title "{书名}" --genre xuanhuan --webnovel-template xuanhuan
```

## Important Notes

1. **保持交互友好**：
   - 使用表情符号和清晰的格式
   - 避免过于冗长的输出
   - 提供明确的下一步操作建议

2. **匹配度分析要客观**：
   - 不要为了讨好用户而给出不实的匹配度
   - 如果不匹配，明确指出哪里不匹配
   - 给出具体的修改建议

3. **支持灵活的用户输入**：
   - 用户可能说"方案1"、"第一个"、"就这个"等，都要能识别
   - 用户可能随时改变主意，要能处理中断和重新开始

4. **书籍删除要谨慎**：
   - 回退重新生成时，删除书籍要使用 `--force` 参数跳过确认
   - 但在删除前，最好在输出中告知用户"将删除已创建的书籍"

5. **与现有技能协同**：
   - 本技能完成后，用户可以继续使用 `fanqie-topic-advisor` 进行选题优化
   - 本技能创建的书籍，可以直接用于 `write-publish-export` 技能
